02 How a request travels

What happens when someone opens https://stockwatch.escu.party:

→

Static sites stop at Caddy, which reads the files from disk. Apps sit behind Caddy on a private Docker network and have no ports of their own.

03 DNS (Cloudflare)

The domain was bought at Cloudflare, so Cloudflare is who the internet asks about it. Only two records exist, set once and never touched again:

TypeNameTargetMeaning
CNAME@the .go.ro nameescu.party itself
CNAME*the .go.ro nameevery subdomain, existing or future
Why point at the .go.ro name instead of an IP? The home IP can change. The ISP's dynamic DNS name always follows it, so escu.party follows too, with no update scripts.

Proxy status: currently orange (proxied). Cloudflare stands in front, which hides the home IP. Set SSL/TLS → Full (strict) so Cloudflare talks HTTPS to the server and checks its certificate. If streaming in an app ever stutters, switch that one record to grey (DNS only).

04 Router

  • Port forwarding: TCP 80 and 443 → the server's LAN IP. Nothing else is forwarded.
  • 80 is needed so Let's Encrypt can verify the domain and so http:// can redirect to https://.
  • NAT loopback works on this router, so the public names also work from inside the house.
  • The server needs a fixed LAN IP (DHCP reservation) or the forward breaks.

05 Caddy, the front door

Caddy runs in Docker (caddy:2-alpine) and is the only thing that listens for web traffic. Config: ~/homelab/web/Caddyfile. Folders are mounted read-only into the container.

Automatic HTTPS

Writing a site as a bare domain name is all it takes. Caddy gets a free Let's Encrypt certificate, renews it before it expires, and redirects HTTP to HTTPS.

# a public static site
escu.party {
	root * /escu.party
	file_server
}

# an app behind a password
stockwatch.escu.party {
	basic_auth @locked {
		user  $2a$14$…bcrypt-hash…
	}
	reverse_proxy stockwatch:8000
}

# plain HTTP for the home network only; everyone else is dropped
:80 {
	@home client_ip private_ranges
	handle @home { import routes }
	handle       { abort }
}

The container setup

  • Read-only filesystem, all Linux capabilities dropped except binding to low ports, 128 MB memory cap.
  • Certificates live in a Docker volume (caddy_data), so restarts don't re-request them.
  • Apps join the homelab-web Docker network and are reached by container name. They publish no ports.

06 Security

  • Password on StockWatch: browser login prompt (HTTP Basic Auth over HTTPS). Only the bcrypt hash is in the config.
  • Install files are exempt: manifest.json and the icons skip the password, otherwise "Install app" breaks (see gotchas). They contain nothing private.
  • Bare public IP is blocked: requests that don't use a known name and don't come from the home network get the connection dropped.
  • Hidden files: .git, dot-files and agent folders are never served from virus.escu.party.
  • SSH is only allowed from the LAN (ufw). Remote admin goes through Tailscale, never the open internet.
  • API keys for apps live in .env files that are never committed.
Docker skips the firewall. Published Docker ports are opened by Docker's own rules, which run before ufw. A "deny" in ufw does not protect a published container port. That's why apps publish nothing and Caddy does the filtering.

07 Add a new subdomain

Thanks to the wildcard, nothing changes in Cloudflare. Everything happens on the server:

  1. Put the files in a folder (or start the app container on the homelab-web network).
  2. For a folder, mount it in ~/homelab/web/compose.yaml: - ../myfolder:/myfolder:ro
  3. Add a block to the Caddyfile: 
    newthing.escu.party {
	root * /myfolder
	file_server
}
  4. Check and apply: 
    cd ~/homelab/web
sudo docker run --rm -v $PWD/Caddyfile:/etc/caddy/Caddyfile:ro caddy:2-alpine \
  caddy validate --config /etc/caddy/Caddyfile
sudo docker compose up -d          # picks up new mounts
sudo docker compose restart web    # picks up Caddyfile changes
  5. Wait ~30 s for the certificate, then open https://newthing.escu.party.

09 Gotchas we hit

HTTPS on the LAN IP "just hangs"

Nothing listened on 443 for the IP, and the firewall silently drops instead of refusing, so the browser waits forever. Browsers also try HTTPS first, which made plain HTTP feel slow. Certificates are issued for names, not private IPs, so the fix is a real domain.

The domain pointed at an old IP

Let's Encrypt reported "Timeout during connect". The DNS record held a stale IP. Always compare dig +short name with the real public IP first.

A fresh domain "doesn't exist" for a while

Visiting a name before its record existed made the router's DNS cache the answer "no such name" (up to 30 min, sometimes longer). nslookup name 1.1.1.1 proves the record is fine. Fix: wait, reboot the router, or run ipconfig /flushdns. Testing on mobile data skips the router.

Caddy ran the "block outsiders" rule last

Caddy sorts directives into a fixed order. abort (and even a route block) ended up after handle, so outsiders still reached the app. Fix: make the choice with mutually exclusive handle @home { … } / handle { abort } blocks. Always test the deny path, not just the allow path.

Config change ignored after caddy reload

The Caddyfile is bind-mounted as a single file. Tools like sed -i write a new file, and the container keeps seeing the old one. Restart the container after such edits.

"Install app" stopped working behind the password

Browsers fetch manifest.json and icons without sending the login, got a 401, and decided the site wasn't installable. Fix: exempt just those files from basic_auth.

git pull refused: "Not possible to fast-forward"

The GitHub history had been squashed, so local and remote no longer shared commits. After checking that GitHub had everything, the clone was reset to origin/main with a backup branch kept.

10 Cheat sheet

# where things are
~/homelab/web/Caddyfile        # all routing, HTTPS, passwords
~/homelab/web/compose.yaml     # Caddy container + folder mounts
~/homelab/web/escu.party/      # disco page
~/homelab/web/stock/           # StockWatch app
~/homelab/virusescu.github.io/ # virus.escu.party

# Caddy logs (look for "certificate obtained" or errors)
cd ~/homelab/web && sudo docker compose logs --tail 50 web

# new password hash for basic_auth
sudo docker run --rm caddy:2-alpine caddy hash-password --plaintext 'NEW-PASSWORD'

# what does the world think this name is?
dig +short stockwatch.escu.party @1.1.1.1

# test a site through Cloudflare, bypassing a stale local DNS cache
curl -I --resolve escu.party:443:<cloudflare-ip> https://escu.party/
