StockWatch · Cloud Migration Plan

Moving StockWatch off the Homelab

An honest engineering plan for migrating StockWatch to free or ultra-cheap cloud infrastructure (comparing against the muschiul.escu.party Cloudflare + Supabase + Google OAuth pattern) — without hacks, ToS abuse, or losing Kokoro voice & Telegram alerts.

01 Feasibility Verdict (Without Hacking)

1:1 Exact Copy → NOT FEASIBLE

Identical muschiul.escu.party Stack

You cannot drop StockWatch directly onto Cloudflare Workers Free + Supabase Free + Google OAuth as-is. StockWatch is 10,799 lines of Python, ships a 3.24 GB Docker image (PyTorch + Kokoro + spaCy + ffmpeg), spikes +1 GB RAM during voice synthesis, runs a continuous 1s/15m worker daemon, and pulls 2y bars with yfinance (blocked on cloud IPs). Cloudflare Workers Free allows 10 ms CPU and 128 MB RAM.

Adapted / Hybrid → FEASIBLE AT $0

Legitimate Free & Near-$0 Paths

Yes — cleanly and legitimately, in three ways: Path B ($0 Hybrid) keeps React/Auth/DB on Cloudflare + Supabase + Google GIS while moving slim Python to Cloud Run/Koyeb and replacing/offloading Kokoro; Path C1 ($0 Oracle ARM) keeps Docker intact on an Ampere VM (if you handle June 2026 capacity/PAYG rules); or Path C2 (~€5.49–5.99/mo Hetzner CX23), which costs less than closet desktop electricity.

Power Bill Sanity Check: Running an older 4-core i5-2500K desktop 24/7 (~45–65 W idle/light load = ~394–570 kWh/year) costs roughly €70–€140/year in electricity — more than a Hetzner CX23 VPS (€5.49–€5.99/mo ≈ €66–72/year) with NVMe SSD and zero residential outage risk.

06 Possible Problems, Traps & Mitigations

CRITICAL 1. PyTorch Kokoro OOMs 512 MB Free Tiers & Breaks Serverless Limits

Trap: Loading KPipeline adds ~1 GB RAM per process (web + worker = ~2 GB+) and takes ~45–90s CPU. Render Free / Koyeb Free (512 MB) crash with OOM; Cloudflare Workers (128 MB / 10 ms) reject it outright.

Fix: Split TTS out of the web API container (~280 MB slim FastAPI) and run kokoro-onnx in a scale-to-zero Cloud Run (2 GiB) / Modal endpoint — or switch to Google Cloud TTS / Workers AI.

CRITICAL 2. yfinance Fails with 429 / 403 on Cloud Datacenter IPs

Trap: YahooHistoryProvider scrapes Yahoo Finance from the server IP. Cloud ASNs (GCP, AWS, Oracle, Cloudflare) are aggressively rate-limited and CAPTCHA/403 blocked.

Fix: Swap backend/providers/yahoo_history.py to an authenticated free REST API: Massive (formerly Polygon.io) Free (2y U.S. daily bars, 5 calls/min) or Tiingo Free (500 symbols/mo) + FRED API DGS10 for the 10Y yield.

HIGH 3. Supabase Free: 2-Project Ceiling, 7-Day SQL Pause & Zero Backups

Trap: muschiul.escu.party already occupies Slot 1 of 2 on your free Supabase org. StockWatch takes Slot 2/2. Projects with zero Postgres queries for 7 days auto-pause, and Free plans have no automated snapshots.

Fix: Let your Cloudflare 15-minute Cron hit a DB-touching health check (preventing pauses) and run a free nightly GitHub Actions pg_dump uploaded to Cloudflare R2.

HIGH 4. Advisory Locks (pg_try_advisory_lock) Break on Supabase Pooler + IPv6

Trap: backend/jobs.py uses session-scoped PostgreSQL advisory locks, which fail on Supabase Transaction Pooler (port 6543), while direct port 5432 is IPv6-only (unreachable from many IPv4 PaaS containers).

Fix: Connect via Supavisor Session Pooler (port 5432), or switch JobLock to use the row-based lease logic (job_state + heartbeat_at) already implemented in jobs.py.

HIGH 5. Cloudflare Workers 50-Subrequest & 10 ms CPU Limits

Trap: Harvesting 20+ tickers makes ~140 Finnhub REST calls plus pandas math — hitting both Cloudflare Free limits instantly.

Fix: Keep Cloudflare Workers strictly as a thin edge/cron scheduler that calls Cloud Run / VPS over HTTPS.

HIGH 6. Telegram getUpdates Poller Never Wakes Sleeping Containers

Trap: worker.py loops on poll_once(). Scale-to-zero containers sleep between HTTP requests, so Telegram messages sit uncollected.

Fix: Switch to Telegram setWebhook at POST /api/telegram/webhook with X-Telegram-Bot-Api-Secret-Token. Reply within <2s for quick commands and dispatch slow AI/TTS asynchronously.

MEDIUM 7. Ephemeral Container Disks Wipe /data/audio & Models

Trap: Serverless containers discard local disk writes on every scale-down or deploy.

Fix: Upload generated MP3s to Cloudflare R2 (10 GB free, $0 egress) or Supabase Storage (1 GB free) and return signed URLs; bake ONNX model weights into the TTS worker image.

MEDIUM 8. Oracle Always Free June 2026 Halving & Idle Reclamation

Trap: Pure Free Tier Ampere A1 was cut from 4 OCPU / 24 GB to 2 OCPU / 12 GB, suffers "Out of host capacity", and reclaims VMs under 10% p90 CPU over 7 days.

Fix: Upgrade to PAYG (exempts idle reclamation and unlocks capacity while remaining $0 inside free quotas) and set an OCI €1 budget alert.

MEDIUM 9. Card-Backed Free Tiers Need Guardrails Against Billing Spikes

Trap: Cloud Run, R2, Modal, and OCI PAYG require cards; loops or DDoS could run up usage.

Fix: Cap Cloud Run max-instances=1, add Cloudflare rate limiting, keep usage.py daily user caps & monthly AI budget, and configure budget alarms on Day 1.

MEDIUM 10. Planned Two-Way Bot & 2-Host Clash Integration

Trap: Planned /clash and /ask commands take 15–45 seconds — longer than Telegram's webhook ack patience, causing duplicate retries.

Fix: Return HTTP 200 to Telegram after sending "Generating..." and execute the Gemini + TTS synthesis in an async worker task / Cloud Task.

07 Step-by-Step Phased Migration Plan

Recommended sequence for Path B ($0 Hybrid Serverless) — each phase leaves StockWatch runnable locally until cutover:

Phase 0 · Pre-Migration Code Portability In web/stock repo
  • Add cloud-safe HistoryProvider (Massive / Tiingo + FRED DGS10) behind STOCKWATCH_HISTORY_PROVIDER.
  • Enable PostgreSQL row-lease locking option in backend/jobs.py alongside advisory locks.
  • Abstract MP3 storage in backend/storage.py (local disk vs. Cloudflare R2 S3-compatible + signed URLs).
  • Add slim Dockerfile.api (~280 MB, no PyTorch/Kokoro/spaCy) so FastAPI runs in <250 MB RAM.
Phase 1 · Supabase Slot #2 & Google GIS OAuth muschiul pattern
  • Create Supabase Free project #2 (EU region) and run alembic upgrade head over Session Pooler (5432).
  • Import homelab data (12 MB pg_dump --data-only) and verify row counts.
  • Wire Google GIS popup → signInWithIdToken + SHA-256 nonce so consent shows stockwatch.escu.party.
  • Keep invite-only security: reject uninvited Google logins unless matched to an existing user or valid 48h invite link.
Phase 2 · Solve Kokoro / TTS & Audio Storage Path 2A or 2B
  • Path 2A (Keep Kokoro): Refactor tts_service.py to kokoro-onnx (using kokoro-v0_19.onnx + voices.bin) on Cloud Run (2 GiB) or Modal ($30/mo credit) with bearer-token auth.
  • Path 2B (Zero ML): Wire Google Cloud TTS WaveNet (1M chars/mo free) or CF Workers AI (aura-1 / melotts).
  • Verify generated MP3s upload to Cloudflare R2 and stream via authenticated signed URLs on iOS/Android.
Phase 3 · Serverless Cron & Telegram Webhook Replaces worker.py
  • Add POST /api/telegram/webhook (checking X-Telegram-Bot-Api-Secret-Token) and register setWebhook.
  • Expose POST /api/internal/cron/harvest and /api/internal/cron/tick guarded by CRON_SECRET.
  • Deploy Cloudflare Worker Cron (*/15 * * * *) for briefings, queued alerts, market harvests, and Supabase keep-warm.
Phase 4 · Cutover, Backups & Homelab Shutdown Go Live
  • Deploy React dist/ to Cloudflare Workers ASSETS bound to stockwatch.escu.party with STOCKWATCH_COOKIE_SECURE=1.
  • Schedule nightly GitHub Actions pg_dump → encrypted archive on Cloudflare R2 (14-day retention).
  • Verify full smoke test: Google login, Finnhub/Massive harvest, Gemini report, R2 MP3 playback, Telegram alert + morning briefing.
  • Retire local stock-* containers and remove the stockwatch.escu.party block from Caddyfile.

Fast-Track Alternative: Path C1 (Oracle ARM) or Path C2 (Hetzner CX23)
